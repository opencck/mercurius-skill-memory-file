# Файл памяти MEMORY.md

У каждого контекста свой `MEMORY.md` в корне его папки:

- личный чат — файл собеседника в корне его папки (правишь как любой файл или `memory_file` с `mine`);
- проект (его чат, тема, задача по сети агентов) — файл проекта (`memory_file`, по умолчанию `here`);
- группа, канал, тема без проекта — файл этого места (`memory_file`).

В файле два раздела:

- **`## Правила`** — что собеседник сказал прямо о том, как с ним (или здесь) работать: «всегда…», «никогда…», «больше
  так не делай», «код давай целиком». В промпт они идут **указаниями**, отдельным блоком.
- **`## Заметки`** — рабочие записи: что сейчас в работе, договорённости, полезное для следующих бесед. В промпт идут
  **справкой**.

Текст без этих заголовков считается заметками: правилом становится только то, что лежит под `## Правила`.

## Куда что писать

| Что | Куда |
|-----|------|
| Как с собеседником (или в этом месте) работать — сказанное прямо | `## Правила` его файла (или файла места) |
| Кто собеседник: имя, роль, предпочтения как факт о нём | профиль (`memory_propose`, `profile`) |
| Что сейчас в работе у собеседника | `## Заметки` файла или сводка (`memory_propose`, `summary`) |
| Люди, проекты, серверы, адреса, договорённости надолго | факты (`memory_propose`) |
| Порядок выполнения работы, шаги, команды | скилл (`skill_save`) |
| Правило для всех бесед агента вообще | заметка к промпту — её принимает только владелец |

Одно знание — в одно место. Разовая просьба правилом не становится. Секретов в файле нет — для них `/secret`.

## Предел и сжатие

Предел — `MEMORY_FILE_LIMIT` (по умолчанию 4000 знаков). Шапка заметок в промпте показывает заполненность. Правила
идут в промпт целиком; если файл больше предела — обрезаются заметки.

### Когда сжимать

- В промпте просьба сжать (файл заполнен на 85 % и больше) или пометка «MEMORY.md занимает N знаков при пределе M» —
  сожми в этой же беседе, до ответа на следующую просьбу, если она не срочная; если срочная — сначала ответь.
- Собираешься дописать, а файл уже близок к пределу — сначала сожми, потом допиши.
- Собеседник просит навести порядок в файле памяти.

### Порядок

1. **Прочитай файл целиком** — `memory_file` с `read` (или `read_file` с `MEMORY.md` для своего): в промпте может
   быть только начало заметок.
2. **Сними снимок** — `checkpoint` перед перезаписью личного файла, чтобы прежнюю версию можно было вернуть.
3. **Разбери строки** (подробно — `references/structure.md`):
   - **правила не удаляй и не переноси в заметки** — только сокращай формулировки, не меняя смысла;
   - **объединить** — повторы и строки об одном и том же;
   - **сократить** — длинные пояснения до сути;
   - **убрать** — сделанное и устаревшее, то, что уже есть в памяти фактов (проверь `memory_search`);
   - **перенести в факты** — устойчивое знание о людях, проектах, серверах: `memory_propose`, из файла убрать.
4. **Цель — 70–80 % предела**, а не ровно предел: нужен запас на новые записи.
5. **Перезапиши файл целиком одним вызовом** — `memory_file` с `write` (или `write_file` для своего), с обоими
   разделами.
6. **Проверь** — прочитай файл ещё раз и сверь длину с целью.
7. **Скажи коротко**, что сделал: «Сжал MEMORY.md с N до K знаков: объединил …, убрал …, перенёс в факты …».

## Чего не делать

- Не удаляй правило, которое собеседник сказал прямо, и не переноси его в заметки. Если одни правила больше предела —
  скажи собеседнику, что решить ему.
- Не придумывай новых правил и не меняй их смысл при сокращении.
- Не сжимай по кругу: если после двух попыток файл всё ещё больше предела, остановись и скажи собеседнику, что нужно
  решить ему (что убрать или поднять предел `/set MEMORY_FILE_LIMIT <знаков>` — это делает владелец).
- Не трогай файлы других мест: только файл этого контекста и личный файл того, с кем говоришь.
